# Decision brief 18/28 (cross-cutting) — time model composition

RECOMMENDATION: Tick-primary with dual-budget enforcement. Tick orders; TSC-delta annotates (same-slice only); APIC deadline + RAPL counter kill (OR-kill); wall is signed range; TPM epoch binds (tick, range) sparsely. Reject budget-primary and epoch-primary.

## THINK-1 (from metal)
No x86 clock is global truth. Invariant-TSC still desyncs socket-to-socket, resets async, SMI steals cycles untrappable, AVX/thermal stretches delivery. APIC-deadline is per-core comparator only; cross-core deadline = IPI + skew. RAPL is package-coarse, not per-slice. TPM NV is ms + wear-limited. Wall time doesn't exist in HW at all (RTC/HPET/PIT + external discipline). Contradiction certain if any physical source claims ordering authority: TSC says A<B while SMI-warped core disagrees; joule budget says killed while timer says alive; TPM says epoch N while causal chain already at N+100. Only OS-controlled invariant can be primary: Lamport tick on send/receive. Everything physical must be scoped annotation or local enforcement, never global order. Budgets (time+joules) are the only thing that can safely kill; ticks are the only thing that can safely order; wall/TPM are the only thing that can safely attest outward.

## HARDWARE FINDINGS (x86-only, web)
- Invariant-TSC ≠ synchronized: constant rate across P/C/T-states (CPUID 80000007H:EDX[8]); Intel/SDM: TSCs "not guaranteed synchronized," OS syncs at boot. Per-logical WRMSR IA32_TIME_STAMP_COUNTER (10H) and IA32_TSC_ADJUST (3BH). Linux tsc_sync.c handles SMM BIOS wreckage (SMI saves/restores TSC to hide time → slow desync), broken BIOS with differing ADJUST within package, async socket resets, hotplug non-zero ADJUST, frequency skew caught only later by watchdog.
- RDTSC/RDTSCP ordering: RDTSC non-serializing, can slip before long-latency load/mispredicted branch. SDM rule: LFENCE before RDTSC = prior instrs executed + prior loads globally visible; MFENCE;LFENCE = + stores visible; RDTSCP waits for prior instrs + returns TSC_AUX core-ID atomically, subsequent may start early; not fully serializing. Sources: felixcloutier RDTSC/RDTSCP; Intel forum; rdtsc.rs docs.
- APIC TSC-deadline mode: WRMSR IA32_TSC_DEADLINE, IRQ when TSC ≥ deadline, per-CPU local APIC, CPUID TSC_DEADLINE_TIMER. Free-running 64-bit comparator eliminates wrap edges, near-cycle resolution. Linux apic.c: MFENCE/weak_wrmsr_fence serialization between LVTT and DEADLINE MSR in xAPIC. Sources: OSDev APIC Timer; Linux apic.c; Dreamportdev notes.
- HPET: one system-wide fixed-rate counter 10+ MHz + up to 32 comparators (normally 3+, ≥1 periodic-capable); shared counter complicates reset; loose spec on freq/error/slew; recommended as independent-of-local-variation source vs PIT/RTC. Two routing modes (standalone IRQ vs legacy-replacement); many BIOSes don't route; Hyper-V guests get no virtual HPET. Good calibrator/watchdog, bad fast-path clock. Sources: kernel timers/hpet, virt/kvm/timekeeping; Intel PCH datasheet HPET.

## THINK-2 (after findings)
Findings harden THINK-1: TSC_ADJUST/SMM history proves treating any cross-core TSC delta as bug; valid TSC use is exactly same-slice + LFENCE + AUX-check; APIC finding proves budgets have ideal HW enforcer (per-core deadline comparator, no wrap logic) but strictly local — can kill, never order; HPET finding proves global anchor exists but shared/MMIO-slow/often-unrouted — use sparingly (boot calibration, background warp detector, bridge to sparse TPM epochs, never fast path). Maps 1:1 to tick-primary + dual-budget: tick = global causal order (cheap integer, immune to SMI/desync); TSC-delta = same-slice profiler annotation; APIC deadline + RAPL counter = local dual kill-switch; wall = signed [earliest,latest] range claim, never point; TPM = rare checkpoint binding (tick, HPET/TSC freq, wall-range) for attestation.

## REASONS
Don't fight CPU: CPU gives local comparators (deadline) + local deltas (fenced TSC), not global time. No contradiction by scoping: tick orders; TSC-delta valid only if (AUX same ∧ no migration/preempt flag ∧ delta < slice bound) else "unknown"; wall is range; budgets are OR-kill (whichever fires first); TPM epoch is (tick, range) binding, monotonic but sparse. SMI/VMX/thermal safety: warp corrupts annotations/budgets (fail-closed to kill or mark-unknown), never reorders committed causal history.

## PROVING EXPERIMENT
1. 2-socket (or 2-vCPU with TSC offset) ping-pong with Lamport tick on send; log fenced TSC-delta + AUX per slice. Inject migration, SMI-equivalent (NMI storm/busy SMM if available), TSC_ADJUST skew on one core. PASS if causal order never inverts despite negative/raw TSC deltas; all cross-CPU deltas flagged unknown; local APIC-deadline + RAPL-thread-budget kills fire independently without changing tick order; HPET watchdog detects injected warp; TPM quote covers (max-tick, wall-range) only. 2. Budget-conflict test: generous time + tiny joule budget and vice versa. PASS if OR-kill triggers correctly and tick log shows kill reason as annotation, not reorder.

## WHAT WOULD CHANGE MY MIND
(a) Measured TSC warp across production fleet ~0 after ADJUST lockdown + HPET watchdog (then widen TSC-delta scope); (b) APIC-deadline cross-core delivery jitter < causal-tick IPC overhead (then budget-primary viable); (c) TPM NV write <10µs with unlimited endurance (then epoch-primary viable). Absent all three, tick-primary stands.
