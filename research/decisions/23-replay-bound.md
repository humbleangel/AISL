# Decision brief 23/28 (cross-cutting) — replay bound

RECOMMENDATION: ADAPTIVE-DOWN-FROM-TIGHT, FAIL-CLOSED (one bound set). Default TIGHT, shrink only, never grow past hardware-atomic size. Enforced by VMM/OS + verifier, not the lane.

## THINK-1 (from metal)
Replay is not free: unfiltered PT is GB/s of TNT/TIP/FUP+CYC/MTC; buffers are MBs — that mismatch IS the bound. If slice unbounded, replay unexecutable (decode explodes, one ToPA overrun poisons whole epoch, SMM/PMI/thermal/AVX wobble makes cycle-exact re-execution diverge). Hardware already tells the answer: LBR tiny (32), PT output ToPA-chained 4KB–4MB pages with interrupt-on-switch, overflow lossy. Don't fight it: fit the unit in what hardware emits atomically without interrupt race. TSC cannot be truth (invariant ≠ synchronized, VMX offset/scaling perturbs, SMM steals invisibly) — replay clock must be retired-branch + CYC/MTC ordered, TSC only correlation hint. Who enforces matters more than the number: lane under test cannot enforce its own bound — enforcer must be higher privilege owning TraceEn, ToPA, PMI (OS/VMM + offline verifier); lane just halts. Prior lean right: filtered slice + hard cap + fail-closed on OVF/truncation. Open question only TIGHT vs LOOSE vs ADAPTIVE: LOOSE (sampled replay) breaks Thompson (attacker hides in unsampled gap); ADAPTIVE alone risks adaptation logic becoming new trusted unbounded path.

## HARDWARE FINDINGS (x86-only, web)
- LBR depth/options: ring of FROM/TO+metadata MSRs, continuously overwritten, TOS pointer. Depth by generation: Netburst-Merom 4, Nehalem-Haswell 16, Skylake+ 32, Atom 8. Skylake adds timed-LBR (cycles between branches). Perf -b / --call-graph lbr. Architectural LBR enumerated by CPUID leaf 1CH. PT can synthesize virtual arbitrary-length LBR (--itrace --branch-history). Sources: Intel Runtime Optimization Blueprint LBR; LWN Kleen LBR series; LWN Architectural LBR (CPUID 1CH).
- ToPA / buffer sizing + overflow: single ToPA entry limited to power-of-2 up to 4MiB (MAX_PAGE_ORDER); larger = logically concatenated buffers + interrupt to switch; slow switch → last packet truncated, next buffer starts with PSB; default perf auxtrace mmap 4MiB. perf "has no way to slow down the CPU, so when trace bandwidth > disk bandwidth there will be gaps"; long traces take very long to decode — work with short traces. Sources: perf-intel-pt(1) man page; Intel ECI troubleshooting PT docs.
- Overflow packet unreliable: OVF expected on internal-buffer overflow, but errata (TIP/FUP dropped WITHOUT OVF; CBR dropped/inserted without OVF; 2nd byte of CYC drop; OVF itself lost if overflow precedes TraceStop; PSB+ lost on disable race). Workaround: IA32_RTIT_CTL.CYCEn=1 so lost CYC more likely raises OVF. PTWRITE-in-loop floods internal buffers → small slowdown, then timeout emits overflow and resumes (Intel support reply). Sources: Tiger Lake Spec Update TGL006/TGL050/TGL052; Intel Community PTWRITE thread.
- PTWRITE / filtering (how to stay under GB/s): opt-in packets (ptw, fup_on_ptw, pwr_evt, branch, tnt_disable to kill TNT, cyc/noretcomp/cyc_thresh/mtc/mtc_period/tsc/psb_period, IP-range filter/start/stop). Power/PTWRITE decode via intel-pt-events.py, perf script --itrace. Sources: perf-intel-pt(1) config terms; /sys/devices/intel_pt/format + caps; Intel ECI PT filter examples.
- VMX TSC offset/scaling vs PT/replay: Skylake-SP erratum SKX87 (VMX TSC scaling/offsetting corrupts Intel PT packets; fixed/not-listed from Gen2 Xeon on). General rule: invariant TSC ticks constant and across cores on modern parts but NOT synchronized across sockets/machines and breaks on migration; Xen tscmode / Onload docs rely on invariant-TSC + no_migrate. Implication: never use guest TSC as replay clock when TSC offsetting/scaling on. Sources: Intel Community SKX87 thread + Xeon Spec Update; Xen xen-tscmode(7); AMD Onload UG1586.

## THINK-2 (after findings)
4MiB is not arbitrary — largest single-ToPA no-interrupt buffer; anything larger reintroduces the race (truncated packet + late PMI) making replay non-atomic. OVF untrustworthy as sole detector (silent drops) → fail-closed must trigger on ANY of OVF, PSB-resync gap, truncated packet on switch, MTC/CYC discontinuity, LBR-vs-PT branch-count mismatch in 32-window. That kills LOOSE. PTWRITE cost (6–10c P-core) → sparse annotation channel, not log channel. ADAPTIVE safe only if adaptation is downward from hard TIGHT ceiling enforced outside lane (upward adaptation reintroduces unexecutable replay exactly when attacker quiet).

## BOUND SET
- PT byte cap per lane per slice: 4 MiB hard. Single ToPA entry, StopOnOverflow + PMI on full. Config: branch-only, tnt_disable where available, IP filter/start/stop to lane code only, psb_period small, CYCEn=1 + MTC + TSC on (OVF reliability + ordering). PTWRITE commit-marker only, fup_on_ptw=1, budget <1k per slice.
- Instruction/cycle cap per slice: ≤1M instructions retired / ≤32K taken branches / ≤5M cycles (whichever hits first ends slice). Rationale: decodes in <1s, LBR-32 window spot-checks any sub-window, CYC/MTC drift bounded across SMM/thermal wobble.
- Dissenter count: 1 = replay, 2+ = epoch abort. One divergent lane triggers deterministic re-execution of that 4MiB slice on 2 verifiers; second dissent or any OVF/truncation/timing-gap fails whole epoch closed.
- Epoch bound: ≤128 slices (≈512MiB PT max) then must commit or abort. Prevents concatenated-interrupt path and unbounded verifier queue.
- Who enforces: VMM/OS owns IA32_RTIT_CTL.TraceEn, ToPA base/mask, PMI handler. Lane cannot clear OVF or extend slice. Verifier owns inst/cycle caps during decode and votes commit/abort. Hardware is sensor only.

## REASONS
Fits the only atomic hardware unit (4MiB, no switch race), makes replay always executable (<1M insn), uses unreliable OVF safely (any gap = abort), keeps TSC out of truth path, leaves no unsampled gap for Thompson-hiding. Overhead high but bounded and predictable — the price of executability.

## PROVING EXPERIMENT
Trace branch-heavy workload (kernel build + AVX burst + stress-ng --matrix) with above config on Skylake+ (32-LBR) and Atom (8-LBR). Inject (a) PTWRITE flood, (b) VMX TSC offset on/off, (c) forced ToPA-full. Pass: 100% slices decode without end-of-log suppression, every injected overflow/truncation/TSC-offset run aborts closed (no silent commit), median slice decode <1s with LBR-vs-PT agreement on sampled 32-branch windows.

## WHAT WOULD CHANGE MY MIND
Filtered-PT for real lane code consistently <50MB/s so 8–16MiB chained slice still decodes in <1s with zero truncation across 10k switches → raise cap to 8MiB. Silicon guarantees lossless OVF (no silent TIP/FUP/CBR drop errata) + SMM-freeze-counter → allow upward ADAPTIVE. Until then, TIGHT ceiling stands.
