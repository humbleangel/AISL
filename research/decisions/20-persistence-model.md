# Decision brief 20/28 (cross-cutting) — persistence model

RECOMMENDATION: COW-APPEND-ONLY as rule, LEASED-COMMITS as discipline, JOURNALED-IN-PLACE as bounded exception. Rule: never overwrite live data — crash-consistent append + per-record hash chain + single 8B root commit via CLWB+SFENCE / Write+FUA+Flush. Discipline: every commit leased (endurance/joule budget, expiry, re-verify on read after expiry/powercut); GC only reclaims expired/verified-dead prefix, rate-bounded. Exception (only): fixed-size hot superblock / allocator root, triple-replicated + CRC, overwrite allowed, and only on PLP-certified path; plus eADR/pmem fast-path where SFENCE alone suffices. Cap: <1% of bytes written.

## THINK-1 (from metal)
NAND can't overwrite: page-write / block-erase — overwrite in place is a lie the FTL emulates via remap+GC. Fighting it = double writes + GC storms + torn pages. x86 atomicity = 8B only — anything larger torn on powercut, so multi-sector update needs journal-before-overwrite or never-overwrite + pointer swing. Volatile caches everywhere: CPU cache → DRAM → SSD DRAM/SLC-cache → NAND — each layer lies about completion unless fenced/flushed to a power-protected domain. Endurance finite and asymmetric: QLC ~0.1–1k, TLC ~1–3k P/E classical floor — every extra journal write is joules + P/E burned forever. Thompson 1984: trust boundary is hardware — don't assume durability the device didn't promise. Inference: rule = append new + verify + swing 8B root; overwrite needs special justification; leases needed because append is unbounded without GC/expiry discipline.

## HARDWARE FINDINGS (x86/storage-only, web)
- NVMe Flush/FUA: Flush = "request volatile cache made non-volatile" (no-op if no volatile cache; if cache enabled + FUA=0 + no Flush, later reads may return older data). Write-complete ≠ durable. Linux maps fsync → REQ_PREFLUSH / REQ_FUA. Sources: NVMe 1.4 §6.8, §5.21.1.6 via Borrill Mar-2026 survey; kernel writeback_cache_control; nvme_flush(2).
- PLP reclassifies volatility: controller guaranteeing cache destaged on power loss makes cache "non-volatile," VWC N/A, Flush no-op. Enterprise = capacitors/supercap + FTL table flush; consumer mostly none. Sources: NVMe spec note; Kingston/Kalstor PLP explainer; HowToGeek 2026.
- Flush-lie evidence: FAST'13 (SSDs/HDDs ignored flush despite O_SYNC, mass serialization errors); Borrill/Tom'sHW Feb-2022 (4× consumer NVMe, write+flush+success → yank cable → 2/4 lost FLUSH'd data: SK Hynix, Sabrent; Samsung/WD with PLP retained); Win7 era EIDE/SATA ignored FUA; Win8 made FLUSH_CACHE compat-mandatory, NTFS switched journal from FUA to FLUSH_CACHE. Sources: FAST'13 final80; Tom'sHW 2022-02-23; Chen OldNewThing 2017-05-10.
- P/E endurance: SLC ~100k, MLC ~3–10k, TLC ~1–3k classical, 3D TLC 3–5k, eTLC 10–30k; QLC ~100–1k classical, modern 3D QLC ~1k, YMTC X3-6070 claims 4k. DWPD: client QLC <0.2, TLC <0.3; DC QLC <0.5, TLC <3; SLC ≥10. Context ~1k QLC/3k TLC = correct conservative floor. Sources: Kingston NAND brief; HP SSD whitepaper; Kioxia Tech Brief 2021; SNIA Endurance WP; Tom'sHW 2024-03-29 YMTC.
- CLWB/SFENCE: CLWB weakly ordered (ordered vs fences/locked RMW + older writes to same line, NOT vs other CLWB/CLFLUSHOPT/younger writes) — need SFENCE → persist barrier (store+CLWB+SFENCE). ADR = memory-controller persistent; eADR = caches persistent, no flush needed; otherwise flush+fence mandatory. Sources: Intel SDM CLWB/SFENCE; Persistent Memory FAQ; PMTest ASPLOS'19; Agamotto OSDI'20.

## THINK-2 (after findings)
Can't trust Flush/FUA on arbitrary consumer NVMe — design must survive acknowledged-but-lost flush. That kills JOURNALED-IN-PLACE as rule (treats journal commit + overwrite as durable after one barrier). In-place overwrite = read-modify-erase-write + FTL GC + torn-write window + double P/E cost; on QLC with WAF>1, journal doubles already-scarce cycles. COW-append aligns with metal: FTL itself is log-structured; sequential append = lowest WAF, no torn overwrite, prefix-recovery via hash chain + 8B root swing. Append's failure is unbounded growth → fixed with leases (every commit carries joule/P-E budget + expiry + re-verify, GC bounded, stale prefix collectable). Lease = accountability for endurance, not just crash order.

## REASONS
Survives flush-lie + torn write + FTL GC; minimizes WAF/P-E; recovery = walk hash chain to last verified prefix.

## PROVING EXPERIMENT — powercut matrix
Fault rig: relay yank + capacitor-drop detector. Drives: PLP enterprise TLC vs consumer QLC/TLC (known liars + good). For each of 3 modes × 2 FUA/Flush settings: write N commits, flush→success→yank at random offsets; reboot, scan (prefix intact? hash chain verifies? torn sectors? phantom success acked-but-gone?); measure loss window, unrecoverable corruptions, WAF via SMART, joules. Pass = COW+lease: zero unverified corruption, loss limited to uncommitted tail, lowest NAND writes. Fail = journaled-in-place shows torn overwrites + flush-lie loss presented as committed.

## WHAT WOULD CHANGE MY MIND
All target drives prove PLP + honored FUA/Flush over 10k yank trials with zero acked-loss, AND QLC P/E ≥4k sustained with WAF≈1 under overwrite workload — then promote JOURNALED-IN-PLACE to co-rule for hot data.
