# Decision brief 28/28 (cross-cutting) — successor/escrow design

RECOMMENDATION: M-OF-N-SPLIT 3-of-5, deadman-gated, owner holds zero. Share-holders (5, none owner): 1× legal custodian, 1× independent auditor/accountant, 1× upstream mirror operator, 1× elected user/community rep, 1× offline paper/vault holder (bank box, different jurisdiction). Shamir 3-of-5 on KEK-recovery auth + 3 physical signatures required for PolicyAuthorize rotation. Seal: TPM seals KEK under PolicyOR[ A: owner+PCR-current, B: (NV-epoch ≥ expiry AND PolicyOR-3-of-5-sigs AND PCR-recovery) ] — branch B only satisfiable after deadman. Unseal triggers (ALL required): (1) NV deadman counter/expiry passes without owner heartbeat (e.g. 90d), (2) public logged declaration (append-only log/mailing list) + 14d veto window where owner heartbeat aborts, (3) 3-of-5 quorum present in ceremony. Death/incapacity = case 1 fires naturally. Drill cadence: quarterly restore drill on isolated x86 board (quorum unseals test KEK copy, verifies PCR-bound boot + NV epoch, then rotates heartbeat). Split-brain rule if owner returns: single-writer — pre-succession owner key wins until Branch-B ceremony completes; post-ceremony successor epoch wins and owner key revoked via NV_Increment + PolicyAuthorize rotation; returning owner becomes contributor, must be re-authorized by new epoch. Anti-collusion: 3 must collude; any 2 cannot; early quorum action without expiry fails PolicyNV; silent action fails public-log + veto; owner coercion fails (owner has no shares to give).

## THINK-1 (trilemma)
Bus-factor vs collusion is the whole trade. Thompson-1984: trust the human+toolchain chain, not just code. Bun lesson: 1 human = velocity + fatal SPOF. OWNER-NAMES-SUCCESSOR: lowest friction, fatal flaws — (a) dead/incapacitated owner can't rotate compromised successor, (b) designated heir incentivized for owner to disappear (folded-successor conflict already rejected), (c) quorum-confirm theater if only owner nominates. SOCIAL-GRAPH: no crisp quorum, Sybil/favor-trading, no mappable TPM policy (web-of-trust endorsements can't produce deterministic policyDigest — fights the CPU). M-OF-N-SPLIT (3-of-5, none held by owner): raises collusion bar 1→3, keeps operability (2 lost/unavailable and still recover); risk is quorum collusion or apathy — both drill-able, death is not. Split-brain killer for all three: owner returns after succession — must have single-writer rule decided BEFORE metal, enforced BY metal.

## HARDWARE FINDINGS (TPM2 only, web)
- Seal = small secret bound to PCR policy. tpm2_create -i seal.dat seals max 128 bytes, object type KEYEDHASH, SIGN_ENCRYPT|DECRYPT cleared — seal KEK/master secret, not disk. Source: tpm2-tools tpm2_create.1.
- Unseal requires satisfying exact policy in policy session: startauthsession --policy-session + policypcr -l <pcrs> + unseal -p session:<ctx>. PCR drift (update/attacker) → unseal fails. Fix composability: PolicyOR + PolicyAuthorize — authorize PCR-set signed by offline authority so policy digest stays stable while allowing signed PCR updates. Sources: tpm2_policypcr.1, tpm2_policyauthorize.1.
- NV monotonic counters only increment, 64-bit, never roll back — even delete+redefine starts at highest-ever value. Usable in policy via PolicyNV (eq/ugt/etc.). Canonical revocation/deadman: key policy = PolicyNV(counter == N); NV_Increment revokes old policy. Source: TCG Practical Guide NV Counter Index; tpm2_policynv.1.
- Implication: don't seal to bare PCRs. Seal to PolicyOR[ owner-auth, (deadman-expired AND quorum-k-of-n) ] with PolicyAuthorize for PCR rotation and PolicyNV for epoch/deadman.

## THINK-2 (after findings)
Hardware votes for M-OF-N: TPM natively does PolicyOR quorum branches + PolicyNV expiry + PolicyAuthorize signer rotation. Owner-names and social-graph require off-TPM fuzzy logic TPM can't enforce — you end up trusting a server anyway. Collusion math with 3-of-5 outward: attacker needs 3 independent parties + deadman window + public log. Owner alone cannot self-coup (holds 0 escrow shares); quorum alone cannot silent-coup (needs NV-expiry + logged trigger). 2-of-3 more operable but 1 compromise + 1 accident = loss; 3-of-5 minimal robust point.

## REASONS
Don't fight CPU: TPM PolicyOR/NV/Authorize compose exactly this. Single-writer epoch rule prevents split-brain. Noncustodial owner + quorum recovery beats both bus-factor and collusion within drill-able bounds.

## PROVING EXPERIMENT (quarterly, ~1hr)
Deadman fire drill on spare machine: advance NV epoch artificially, publish fake trigger log, require 3 holders to unseal test secret and boot recovery image, then owner issues heartbeat-veto and confirms abort path also works. Pass = both branches tested, holders prove they still exist and still can't unseal early.

## WHAT WOULD CHANGE MY MIND
2 consecutive drills fail to assemble 3 holders (quorum apathy) → downgrade to 2-of-4 + shorter veto. 3 holders co-coercible (same employer/country) → reselect holders, not change scheme. Owner demands instant revocability without ceremony → admit you want OWNER-NAMES, accept bus-factor=1 explicitly.
