# Decision brief 09/28 — capability enforcement primitive

RECOMMENDATION: page-capability-MMU — PTE pkey = only capability ref; PKRU = thread-local rights cache; PCID = arena tag; revoke = trusted INVPCID-0/1; CET-SHSTK+ENDBR + compiler WRPKRU-erasure as anti-bypass; arena-scoped (not per-pointer).

## THINK-1 (from metal)
Capability primitive must be HW-enforceable AND language-nameable without a syscall in the fast path. x86-64 truth: no tagged pointers, no CHERI — only HW-tagged refs are PTEs (present/RW/U/S + key bits); segments dead in 64-bit. So unforgeable ref must live in page tables, not pointers. Fast domain switch must avoid PTE rewrite + TLB flush → PKRU (register) + PCID (TLB tag). Revoke must avoid global flush → INVPCID type 0/1. WRPKRU unprivileged is the Thompson hole: untrusted code executing it makes PKU no boundary — language must withhold WRPKRU/RDPKRU + CET pins control flow. Pure-HW PKU fails; pure-language types fail (no revocation, TOCTOU). Rings too coarse (0/3, syscall cost); EPT/VPID is VM-granularity overkill for intra-process arenas. Tentative: PTE key = capability, PKRU = current rights, PCID = arena tag, CET = anti-bypass.

## HARDWARE FINDINGS (x86-only, web)
- PKU: 4 PTE bits → 16 keys/process, pkey 0 default (15 usable). Per-thread 32-bit PKRU: 2 bits/key (ADi/WDi). RDPKRU/WRPKRU ECX=0, require CR4.PKE=1, 64-bit only. Data-access only, no NX enforcement. WRPKRU fully unprivileged → "useless if attacker controls PKRU or can execute arbitrary instructions" (man7 pkeys.7). Cost: WRPKRU ~20 cycles vs mprotect >1000 cycles + linear in pages; PKRU switch O(1). WRPKRU relatively expensive vs RDPKRU, light speculation barrier → kernel skips if unchanged. XSAVE-managed (XCR0 bit 9), signal-reset weirdness, AMD vs Intel XINUSE[9] divergence. Sources: man7 pkeys.7; kernel protection-keys.txt; felixcloutier RDPKRU; Castes Diving into MPK; libmpk paper; LKML/KVM thread; Oracle Linux blog.
- PCID/INVPCID: 12-bit PCID in CR3[11:0], 4096 values, CR4.PCIDE=1. INVPCID 4 types (0=addr+PCID, 1=single PCID, 2=all+globals, 3=all-no-globals), privileged (CPL=0). Cost: global invalidate i3-9100F ~1600cyc CR3 vs ~1000cyc INVPCID; Ryzen ~900 vs ~400. Type 0/1 ≈2× cheaper than full flush, preserves other PCIDs. Sources: felixcloutier INVPCID; Intel Vol3A 4.10; Haiku review 10451.
- CET: master CR4.CET=1 + CR0.PE=1, then IA32_U_CET/S_CET (SH_STK_EN, ENDBR_EN, SUPPRESS). Shadow stack: CALL pushes both stacks, RET compares else #CP; pages must be Shadow-Stack RO+Dirty or #PF; WRSS only with SHSTK. Kernel CONFIG_X86_CET/SHADOW_STACK, arch_prctl, per-thread inherit, glibc loader enables; 64-bit only. Sources: Intel CET Spec 334525-003; kernel shstk docs; Edgecombe patches.
- STLB sizes: Skylake 1536-entry 12-way shared; Gracemont 48-entry L1 + 2048-entry L2; Golden Cove 96 DTLB/128 ITLB + 2048–4096 STLB. Miss cost: L1 0–1, STLB 5–12, walk 20–200+ cycles — retaining entries via PCID matters. Sources: TACO'23 MMU Handbook; Chips&Cheese; AnandTech.

## THINK-2 (after findings)
16 keys kills per-object caps → arena-scoped (key = arena; language maps many objects → one key; epoch + PCID multiplexing past 16 live arenas). Unprivileged WRPKRU kills pure-HW story → anchor works only if AISL compiler never emits WRPKRU in untrusted code and CET/ENDBR + shadow stack block ROP gadgets — exactly OS+language-as-one (language removes instruction, OS pins CET). INVPCID privileged kills userspace-revoke → revoke = syscall to trusted runtime doing type 0/1 (rare; switch frequent at 20cyc vs 1000cyc asymmetry holds). PCID 4096 also finite → pair (pkey, PCID) = capability domain; fits TLB (no flush on switch), fits STLB reach (~16MB at 4K — huge pages for large arenas). CHERI cleaner but not on x86 (fighting CPU); rings alone = syscall per crossing; pure types = no revocation.

## REASONS
Don't fight CPU: uses the only HW-tagged store x86 has (PTE) + cheapest switch (WRPKRU) + cheapest retain (PCID). Revocation real: PTE re-key + INVPCID-0 per page / -1 per arena, no global flush, no mprotect walk. WRPKRU hole closable only because AISL controls toolchain + loader + CET MSRs together.

## PROVING EXPERIMENT (2 days, no full OS)
Linux 6.x + PKU + CET machine. 1 process, 2 arenas (pkey 1,2), measure: (a) WRPKRU switch latency vs mprotect, (b) gadget scan proving untrusted -O2 build contains zero 0F 01 EF/EE + CET ENDBR at all indirect targets, (c) revoke via pkey_mprotect + INVPCID-1 (kernel module) vs full flush with perf TLB-miss delta. Pass: switch <50cyc, revoke preserves other-PCID hits, gadget count 0.

## WHAT WOULD CHANGE MY MIND
CET unavailable on target fleet (no user_shstk in cpuinfo) or loader can't force it → WRPKRU uncontainable → fall back to ring+language types, accept syscall cost. Need >16 simultaneously live mutually-distrusting arenas per thread with no multiplex window → PKU insufficient → EPT-cap or process separation. WRPKRU speculation-barrier cost dominates (>mprotect at arena rate) → pure language enforcement wins.
