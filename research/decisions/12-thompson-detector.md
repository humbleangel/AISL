# Decision brief 12/28 — Thompson-betrayal detector

RECOMMENDATION: Thompson-page-pin. Reject single-toolchain audit, signature-only, behavior-only. Diverse-rebuild same source with independent toolchain, bit-compare (divergence = betrayal, no trust in either toolchain required). Enforce at the X-grant point: hash the 4K about to become executable, compare to DDC-pinned expected hash, refuse X on mismatch. Compiler-pin vs microcode-pin as separate expiry paths.

## THINK-1 (metal + history)
Thompson 1984: attack lives in toolchain binary, source clean by design. Single-toolchain audit is definitionally blind (audits the artifact the attacker sanitized). Signature-only verifies who signed, not what source said (Thompson compiler signs its own betrayal faithfully). Runtime behavior monitoring watches symptoms; Thompson backdoor is two quiet predicates (if compiling login insert backdoor; if compiling compiler insert replicator) with no anomalous storm. Wheeler's answer stands: diverse double-compilation (DDC) — rebuild same source with independent toolchain, bit-compare. Divergence = betrayal, no trust required. AISL on x86-64: execution is a page attribute (NX bit 63 of PTE, CR3-rooted 4/5-level tables) — CPU faults on X-violation regardless of ELF/signature/monitor opinion. So the check must sit at X-grant: hash the 4K about to become executable, compare to DDC-pinned expected hash, refuse X on mismatch. Anything coarser fights the CPU's own granularity. Split expiry: compiler changes alter bytes; microcode updates alter what bytes mean — one pin conflating both forces full re-attestation on either event.

## HARDWARE FINDINGS (x86-focused research, web)
- TPM PCR mechanics (can't be hot-path): PCRs extend-only (PCR_new = hash(PCR_old || digest)); read + extend only, no direct write. Quote = TPM-signed PCR set + verifier nonce via Attestation Key. Measured-boot chain: SRTM→firmware→shim/grub→kernel; GRUB measures commands/cmdlines→PCR8, files→PCR9; systemd-stub/boot measures→PCR 5,11,12,13,15 (+ NvPCR + tpm2-measure.log); Linux IMA extends file measurements, dm-verity/dm-ima covers block targets. Sources: Intel Trust Authority docs; TCG Guidance; kernel tpm_pcr_extend / LWN 2017; systemd, GRUB manual, kernel dm-ima docs. Implication: TPM quote is a slow-device op (LPC/SPI coprocessor, signed quote + nonce round-trip) — infrequent boot-chain anchor, not per-exec gate.
- Per-page enforcement is native: NX/XD = PTE bit 63 (0=executable, 1=data). W^X / IMA-appraisal + dm-verity is the existing kernel pattern: measure at load, enforce at map/exec. Implication: page-hash-before-X adds no new primitive; rides the fault CPU already takes.
- Reproducible-builds state (DDC now practical): kernel reproducibility requires pinning KBUILD_BUILD_TIMESTAMP/USER/HOST, -fdebug-prefix-map/-fmacro-prefix-map, detached module-signing flow, pre-seeded randstruct.seed, CONFIG_BUILD_SALT for vDSO. Debian: ~83% (2015) → ~94% stretch/amd64 → >95% trixie/amd64 (May 2025, reproduce.debian.net) with .buildinfo + CI double-build varying time/host/order/locale. Implication: DDC's historic blocker (nondeterminism) is now engineering, not research.
- Toolchain betrayal is real: Cox ACM Queue Jan 2026 re-ran Thompson's nih.a on V6 Unix (clean 10,724B vs backdoored 12,918B from identical cc.c source). XCSSET (2020, MITRE S0658): infected Xcode projects execute malware at build time; hash-check of output useless. arXiv 2607.24888 (Sep 2026): full trusting-trust via GNU strip (non-compiler build utility, whole-distro scope) — audit must cover build closure, not just cc.

## THINK-2 (synthesis)
TPM gives rooted boot story but cannot see Thompson: betrayed compiler produces correctly-measured, correctly-signed, behaviorally-quiet binary — PCRs attest "we booted what the attacker built." Reproducible-builds progress makes the missing piece cheap: we CAN know what the bytes should be via independent rebuild. Only CPU-honest place to compare is where X is granted. Keep TPM for boot-chain anchor + infrequent quote; move Thompson detection to page-pin at exec-grant (fast local hash compare, no TPM in loop). Feed verdicts into org attested log; reuse substrate TPM-measure for PCRs (no parallel stack). Compiler-pin vs microcode-pin separation load-bearing: microcode ships as opaque blob changing semantics without changing bytes; conflated pins mean every Intel Tuesday invalidates compiler trust.

## REASONS
vs single-toolchain audit: blind to Thompson by construction (Cox rerun, strip paper). vs signature-only: attests provenance, not source↔binary correspondence. vs behavior-only: Thompson payload dormant until trigger; monitoring pays continuous cost for zero rest detection.

## PROVING EXPERIMENT (2 builds, 1 fault)
Take minimal AISL closed artifact. Diverse-rebuild with two independent toolchains (gcc vs clang, or distinct versions/hosts per Debian reprotest model), pinned env via .buildinfo-style record. Inject Thompson replicator into toolchain A only (Cox nih.a pattern or strip-style post-pass). Show: source audit passes, signatures verify, runtime monitor silent — but DDC hashes diverge. Enable page-pin: loader hashes each 4K at PROT_EXEC grant, compares to toolchain-B expected set. Must fault on first divergent page; must boot clean when pins match. Report fault latency, per-exec-map overhead vs one TPM quote baseline.

## WHAT WOULD CHANGE MY MIND
DDC on AISL closure proves non-reproducible (>~5% pages unstable after standard timestamp/path/key/salt fixes) → page-pin has no stable expected value; fall back to signature + IMA while fixing determinism. Per-X-grant hashing exceeds exec-latency budget with no amortization → move pin to load-time file extent + NX-lock, accept coarser granularity. Legitimate microcode updates silently change execution of pinned pages with identical hashes and no version signal → compiler/microcode split insufficient; add explicit microcode-version to pin tuple or abandon page-hash stability claim.
