# Decision brief 24/28 (cross-cutting) — TLB/PCID/VPID budget numbers

RECOMMENDATION: MEASURED-ADAPTIVE with hard 8-live cap. ONE number set per pCPU, steady state: Max live EPTP views 8 (list may hold 512 configured, only 8 resident; 9th activation forces LRU demote + INVEPT single-context + INVVPID single-context; emergency shrink to 4 if walk_duration/completed p95 >300 cycles). PCID static partition (PCID0 reserved, 1 kernel-global, 1 per live view max 8, rest spare; evict = INVPCID type-1 for that PCID only; type-2/3 banned from fast path). VPID/INVVPID discipline per clone (1 VPID per live view per pCPU; ≤32 pages INVVPID type-0 per page + INVLPG where current-PCID, >32 pages or teardown type-1 once; type-2 never in steady state; INVEPT single-context on EPT-side change, never all-context). Large-page policy 4K default, 2M by proof (kernel text, DMA/clone payloads with proven ≥2M contiguity + alignment at BOTH guest and EPT layers get 2M; no 1G in views). Flush rule selective-first with ceiling (individual invalidations up to 32 pages, else single-context; flush-always forbidden; flush-on-demand without counter forbidden; every flush logs pages/type/walk-refill cycles). Counters driving policy per pCPU: L2 STLB miss rate, walk_duration/walk_completed, EPT-violation exits, IPI shootdowns sent/received, 2M-vs-4K miss split. Promotion 4K→2M only if walk share drops ≥10% over 10M instructions; demotion on fragmentation or L1-2M miss spike.

## THINK-1 (from metal)
Thompson trust boundary is the page table. "Don't fight CPU": STLB is ~1.5–2K shared cache, not tagged database. Every live EPTP view = competing working set in same 12-way structure. Every extra PCID/VPID is not free isolation — reduced reach + future invalidation work. Mental model: fanout multiplies misses, misses multiply walks (4-level guest × 4-level EPT = up to 24 refs per STLB miss worst-case; even with paging-structure caches one miss = 60–1000+ cycles). 4096 PCIDs / 64K VPIDs are namespace not capacity (usable capacity = STLB ways; past ~8 active tags = thrash + INVPCID/INVVPID recycle). 512-entry EPTP list is addressability not performance budget. 4K-only self-harms under EPT (1536×4K = 6MB coverage, fatal under nested costs); 2M-everywhere self-harms differently (8-entry I-side per thread on Skylake lineage overflows 5×, fragments). Prior lean right: hard small cap on live views + count refill cost, not just flush cost.

## HARDWARE FINDINGS (x86-only, web)
- STLB sizes: Skylake L2 STLB 1536 entries 12-way shared 4K+2M + 16×1G; L1 ITLB 128×4K + 8×2M per thread; L1 DTLB 64×4K + 32×2M + 4×1G (TACO'23 Table 1). Golden Cove: L1 ITLB 128→256×4K, 16→32×2M; Load DTLB 64→96×4K; L2 STLB +1/3 (~2048 class) — but only half STLB entries cache 2M, other half 1G. Rule of thumb: 1536-entry coverage ≈6MB at 4K, ~3GB at 2M if fully usable. Sources: TACO'23; Intel Opt. Manual rev 050; learn_cpp TLB note.
- EPT walk cost: worst 24 memory refs per guest→host translation (radix-4 2D walk) (ISCA'17 POM-TLB). Measured Skylake with PSC/EPT/Nested-TLB on: 61 cycles (canneal) to 1158 cycles (graph) per L2 TLB miss; avg dTLB-miss ~135 cycles; up to 50% exec time under nested paging (ISCA'17 + arXiv:2002.01073 + TC'24 XGEMINI, 6× vs native 1D walk).
- INVPCID/INVVPID/IPI: INVPCID types 0/1/2/3, INVVPID 0/1/2/3 (felixcloutier/SDM); INVLPG current-PCID only, may over-invalidate, one INVLPG suffices even for >4K page (SDM 4.10.4.2). Latency: EPTP-switch via VMFUNC ~160 cycles; CR3 ~300 cycles with PCID; IPI delivery several 100s cycles, full shootdown microseconds; old over-commit cases 500K cycles (EPTI ATC'18; Amit ATC'17). Linux has no "right" ceiling: tlb_single_page_flush_ceiling trades INVLPG×N vs full-flush + refill — measure walk_duration/completed + trace_tlb_flush (kernel arch/x86/tlb.html).
- PCID exhaustion: 12-bit = 4096, Linux multiplexes recent mms via per-CPU ctxs + generation rollover; exhaustion → global flush; nopcid + broadcast-INVLPGB = #GP — PCID load-bearing (kernel pti.txt, tlb.c; CVE-2026-64229). VPID 16-bit; INVEPT single-context vs all-context is EPT analogue.
- EPTP list: VMFUNC EAX=0, ECX index into hypervisor-configured EPTP list; max 512 entries per 4K page; no VM-exit; no TLB flush on switch (each EPT tags own combined mappings). Sources: Intel 5-Level Paging White Paper §4.4; Xen NFV slides; EPTI work.

## THINK-2 (after findings)
Findings harden THINK-1, with one correction: Golden Cove's 2M-usable STLB is only ~half, so 2M coverage ≈2GB not ~4GB, and 1G has tiny 16-entry partition — kills AGGRESSIVE twice (512 views never fit; naive all-2M pollutes small 2M/L1 partitions + nested-misalignment risk). CONSERVATIVE (4K-only + flush-always) honest but pays worst tax every time (6MB coverage + full refill + IPI microseconds) to save bookkeeping. MEASURED-ADAPTIVE without hard cap drifts to AGGRESSIVE under load (counters lag thrash) — needs ceiling matching associativity physics: 8 = half of 12-way headroom per set with 2–4 hot views + kernel + burst; matches prior 8-view lean and keeps per-pCPU PCID/VPID trivially recyclable.

## REASONS
Fits STLB physics (8 live ≪ 12 ways, leaves kernel + burst); keeps VMFUNC at 160-cycle no-flush fast path; avoids 24-ref walk storms (2M where aligned) without 8-entry iTLB cliff; makes fanout honest by charging refill not just invalidate. 512-view and 4K-only both rejected on measured cycle counts, not taste.

## PROVING EXPERIMENT (1 day, bare metal SPR + Alder Lake)
N-live-views × M-footprint matrix (N=1,2,4,8,16,32; per-view working set 6MB/64MB/512MB; 4K vs aligned-2M), each random pointer-chase + clone/unmap loop. Collect perf walk_duration/completed, EPT exits, IPI count, throughput. A/B invalidation: type-0×N vs type-1 vs full. Pass = knee at N>8 (walk cycles/entry and throughput collapse), 2M-aligned wins ≥15% on large sets but loses/ties on scattered sets, type-1 beats N×type-0 past ~32 pages. Publish knee graph; bake 8/32 as constants with counters above.

## WHAT WOULD CHANGE MY MIND
(a) Walk p95 stays <150 cycles at N=16–32 on target SKUs with PSC absorbing it → raise cap to 16. (b) VMFUNC+combined-TLB measurements show zero cross-view eviction to 64 views → adopt larger list as live. (c) IPI+refill measures < walk savings from sharing → flush-always wins. (d) Workload proves sustained aligned-2M with no L1-2M pressure → default to 2M. Absent one of these, ship 8-live + measured refill.
