# Decision brief 17/28 (cross-cutting) — syscall fate in detail

RECOMMENDATION: DELETE entirely. Clear IA32_EFER.SCE=0. Every SYSCALL becomes #UD (illegal). No STAR/LSTAR/SFMASK to program, no dispatch table to review. All driver/service requests become explicit messages: #UD trap or execute-only / no-access EPT page → EPT-violation VMEXIT → upcall handler.

## THINK-1 (from metal)
AISL premise: OS+language one thing, no user/kernel split in classic sense; Thompson says dispatch table is ideal place to hide compiler-level backdoor. DELETE: SCE=0 → #UD, no MSR state, no table. GATE keeps fast path but keeps all MSR state + CPL-gated dispatch. EMULATE keeps trap plus POSIX semantic layer (maximum TCB). Metal intuition favoring DELETE: SYSCALL/SYSRET is deliberately non-checking (no IDT lookup, no CPL-vs-DPL gate check, no stack switch — trusts STAR/LSTAR/SFMASK + GS), exactly the Thompson surface (whoever controls those 3 MSRs + table controls everything silently); IDT #UD path DOES check (vector through IDT, CPL logic, IST option, full frame) — slower per call but auditable (one vector, one handler, deny-by-default); EPT-violation upcalls expensive (VMEXIT) but only on deliberate boundary crossings, not per-byte (drivers should be mapped shared-memory + rings, never per-call traps); NMI/SMI pierce CLI/SFMASK masking and SYSRET has known race (Linux forces IRET fallback) — disappears with no SYSRET; legacy boot (int 0x80/BIOS) lives only BEFORE AISL takes over.

## HARDWARE FINDINGS (x86-only, web)
- SYSCALL ~1/4 cost of legacy interrupt entry; can be disabled to #UD: "IA32_EFER.SCE must be set, or SYSCALL will result in a #UD exception. IA32_EFER MSR 0xC0000080, SCE bit 0." KVM relies on this (SYSCALL #UDs if SCE=0). Sources: OSDev SYSENTER; Linux arch/x86/kvm/vmx/vmx.h.
- SYSCALL bypasses IDT; INT/fault path does full IDT+CPL+DPL+stack-switch checks. SYSCALL does not consult IDT, pushes no full frame; MSRs STAR/LSTAR/SFMASK configure behavior. INT n checks CPL<=DPL, loads SS:ESP from TSS on privilege change. Linux entry_64: system_call vs interrupt arrays, IST, paranoid SWAPGS/RDMSR handling for NMI/MCE. Sources: kernel-internals.org syscall-entry; i386 PRM INT; kernel.org entry_64.
- VMEXIT ~10x syscall entry; EPT-violation expensive but rare path: hardware round-trip Prescott 3963 → Nehalem 1009 → Westmere 761 → Sandy Bridge 784 cycles; nested/virtualized 9794 cycles ("over 10x worse"); combined HW+SW exit service ~3000 cycles (~0.9µs @3.33GHz). Implication: DELETE trades ~50–150-cycle SYSCALL for ~1–3k-cycle #UD/VMEXIT — correct only if upcalls are infrequent (control plane, not data plane). Source: USENIX ATC12 (Amit et al., ELI/nested virt).
- SYSRET fragile under NMI/MCE (guest-controlled stack race → Linux IRET fallback in syscall_64.c); SMI highest priority (even above NMI), jumps to hard-wired SMM RAM, cannot be intercepted, invisible to OS, can last hundreds of µs. Sources: OSDev SYSENTER; Linux syscall_64.c; Intel ECI Real-Time Scheduling docs.

## THINK-2 (after findings)
Latency numbers confirm tradeoff is frequency not magnitude: DELETE makes each crossing ~10–20x slower, but AISL should have almost zero crossings in steady state (shared rings, mapped queues). Keeping GATE to "save cycles" preserves exactly the state Thompson exploits: 3 writable MSRs + indirect table + SWAPGS fragility + SYSRET-vs-IRET decision logic — hundreds of lines of review surface for a path that should be cold. EMULATE worst: keeps trap PLUS POSIX layer (signal delivery, fork/exec aliasing, vsyscall quirks) — maximum review surface, maximum compiler-trust, zero metal benefit. Driver needs: MMIO/doorbell + interrupt completion, not syscalls — map them, #UD/EPT upcall only for bind/setup/revoke. Legacy: confine to pre-SCE=0 loader stage; after wrmsr(EFER, SCE=0) + LSTAR poisoned, legacy binaries deterministically #UD — fail-closed, observable. "Don't fight the CPU": CPU wants SCE=0 → #UD (documented off-switch); using it is going with the metal.

## REASONS
Smallest Thompson surface (zero indirect dispatch MSRs live at runtime). Smallest review surface (one #UD vector + one upcall gate vs N-entry table + SYSRET/IRET predicate maze). NMI/SWAPGS fragility deleted with SYSRET. Cost affordable iff upcalls are control-plane-only — which the AISL driver model already requires.

## PROVING EXPERIMENT (1 day, bare metal or KVM)
Boot test kernel, wrmsr EFER←SCE=0, poison LSTAR=0xDEAD. Execute SYSCALL from CPL3 → assert #UD (vector 6), handler logs RIP/RAX, kills or upcalls. Port 2 drivers (console + block) to shared-memory + EPT-guard upcall bind; run workload; count #UD/VMEXITs per second via perf counter. Pass: <100/s steady-state, throughput within noise vs GATE build. Attempt Thompson demo: malicious LSTAR write post-fence → must fault (MSR bitmap / CR pinning), proving dispatch cannot be silently re-aimed.

## WHAT WOULD CHANGE MY MIND
Measured hot-loop driver needing <500ns synchronous kernel assist with no batching/mapping alternative (GATE wins on physics); load-bearing binary trapping >10k #UD/s making DELETE de-facto emulation (then GATE narrowly N≤8 allow-listed RIPs + audit counter until it dies); or NMI/#DF/SMI correctness requiring STAR path.
