# Decision brief 25/28 (cross-cutting) — first beachhead image to build

RECOMMENDATION: VAULT-FIRST. Bootstrap order is one-way; vault is the hand seed. Produces the artifact every later image needs: signed UKI + golden PCR 7/11 + pcrlock policy. Smallest auditable TCB fits 1-human review; swarm builds workers against its spec later.

## THINK-1 (dependencies + economics + bootstrap)
Thompson order: trust does not bootstrap backward. Vault produces golden measurements + signing key + ceremony. Worker consumes them (verify/attest/reset-to-known-good). Build worker first = fast reset to an untrusted state — no root to measure against. Technical chain: measured-boot → sealed keys → attested dispatch → disposable workers (vault is node 1). Economics: worker-first = faster cash (CI minutes, volume); vault-first = slower cash but enterprise-grade trust story, signing as choke point for all later images. With 1 human + swarm, constraint is auditability not throughput (swarm generates volume code later; only human does hand-seed ceremony credibly). SINGLE-CORE-IMAGE trap: one binary role=vault|worker flag looks lean but isn't — same measurement with divergent behavior = attestation loses discrimination; vault inherits worker's driver/virtio/network TCB; worker inherits vault's ceremony/key-handling paths; union TCB, harder PCR policy, confused-deputy risk.

## HARDWARE FINDINGS (web, directly relevant only)
- UEFI ExitBootServices is point-of-no-return, fragile handshake: GetMemoryMap() → MapKey → ExitBootServices(MapKey); any firmware event between invalidates key, must retry loop. After success: boot-services memory reclaimable, only Runtime Services survive, drivers must quiesce via EVT_SIGNAL_EXIT_BOOT_SERVICES, no alloc/free in handler. Sources: UEFI spec 2.11 §7; vectree.io ExitBootServices mechanism 2026-03-26; Tianocore EDK2 driver guide.
- TPM-sealed image practice converged: UKI + PCR 7+11 + signed policy, not raw PCR 0/2 pinning. systemd-cryptenroll --tpm2-pcrs=7+11; UKI bundles kernel+cmdline+initramfs measured into PCR 11 by systemd-stub. Raw 0+2+4+7+9 breaks on every firmware/kernel update (re-seal tax). Modern fix: systemd-pcrlock / --tpm2-public-key-pcrs=11 pre-authorizes trusted-signer futures. Implication: golden UKI + measurement log must exist BEFORE any fleet auto-unlock — that's a vault product. Sources: linuxiq.org TPM2/systemd-cryptenroll 2026-02-16; systemshardening.com LUKS-TPM2 2026-04-30; kimiblock blog 2026-01-28; rhjihan LUKS-TPM Debian guide 2026-07-18.
- Attestation-first pattern (Kata/CoCo + Trustee) confirms vault dependency: CVM = measured UKI + kernel cmdline (incl. dm-verity root hash) in attestation evidence; Trustee/KBS releases secrets only on matching policy + initdata hash; image-based rootfs + dm-verity root hash in launch measurement is the current direction. Sources: Red Hat CoCo on bare metal 2026-06-04; confidentialcontainers.org securing-workloads; Red Hat CVM core 2025-09-15; kata-containers PR 12778.

## THINK-2 (after findings)
Hardware raises vault-first value: ExitBootServices minimalism favors vault (tiny driver set, deterministic memory map → stable measurements); worker wants fat virtio/fast path — opposite optimization, so forcing one image forces one bad compromise at the most brittle handoff in x86 boot. TPM practice kills SINGLE-CORE-IMAGE: shared UKI ⇒ identical PCR 11 across roles — verifier can't tell signer from worker from evidence alone; must trust runtime flag, which is exactly what measured-boot is meant to eliminate. Separate UKIs = separate PCR 11 domains = clean policy. "Don't fight the CPU": x86 gives ring/VMX, TPM extend-only PCRs, one-shot ExitBootServices — vault leans into all three (seal, measure, exit-clean); fast-resume fights them (snapshot restores PCR/state consistency problems, live-migration vs sealing). Cash-flow rebuttal survives but narrows: worker-first only wins if runway < time-to-first-vault-ceremony-revenue; vault can monetize early as signed-base-image / ceremony-as-service without worker fleet.

## REASONS
Bootstrap order one-way (vault is hand seed). Produces artifact every later image needs (signed UKI + golden PCR 7/11 + pcrlock policy). Smallest auditable TCB fits 1-human review.

## PROVING EXPERIMENT (falsifying, 2–4 weeks, no fleet)
Build vault UKI v0 + ceremony script: air-gapped keygen → UKI sign → systemd-cryptenroll --tpm2-pcrs=7 --tpm2-public-key-pcrs=11 on reference board → reboot 20× + one kernel bump (re-signed, same signer). Pass = auto-unlock survives signer-consistent update, fails on init=/bin/bash tamper. Foreign machine attest/unseal must fail. Ship measurement log + verifier script to 2 design-partner prospects: "would you pay for images signed by this?" ≥1 paid pilot intent = validated.

## WHAT WOULD CHANGE MY MIND
Worker-first if ceremony has no buyer (0/5 prospects care about attestation, all want $/CI-min now) OR vault ceremony exceeds 8 weeks for 1 human. Single-image only if role-separated PCR domains from one build demonstrated (distinct UKIs compiled from one source tree with role baked into PCR 11, not runtime flag) — vault-first with shared source endorsed; runtime-flag single binary rejected.
