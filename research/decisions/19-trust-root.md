# Decision brief 19/28 (cross-cutting) — trust root semantics

RECOMMENDATION: MEASURED-ONLY with quorum verdicts. Choose MEASURED-ONLY. Never treat quoted PCRs as trust anchor, even with expiry. TPM driver does periodic Quote(nonce_from_quorum) + PCR_Read + eventlog export; trust = quorum function V(E_tpm, E_peers, E_transparency, behavior) with short-lived capability (minutes), renewed by fresh quorum, not by TPM expiry alone. Seal use allowed only as cost-raiser (bind disk key to PCRs), never as verdict.

## THINK-1 (from metal)
Thompson 1984: measurer is code too. On x86 the measurer chain is CRTM → BIOS → bootloader → OS, all mutable except hoped-immutable CRTM. Who measured CRTM? Nobody inside the box can. TPM physics: passive chip across LPC/SPI bus; can Extend (one-way hash append), Quote (sign PCR-hash + nonce), Seal/Unseal (release iff PCRs match). Cannot halt CPU, NMI SMM, inspect ME/microcode, or stop a lying kernel from using an unsealed secret once released. Therefore TPM-PIN (if Quote verifies and PCRs == allowlist then TRUSTED until T+expiry) makes a witness into a judge. Failure modes: blind spot = false-negative free (SMM, ME, microcode, DMA-before-IOMMU never enter PCRs but can own the machine post-unseal); Extend unauthenticated (anyone with bus/reset access can replay good extends — trust collapses to "first writer wins"); latency forces caching (Quote costs ms → hot path cannot quote → PIN must cache verdict for expiry window = attacker window); revocation/supply-chain (EK cert proves genuine TPM, not genuine firmware; allowlist update is outward distribution problem PIN doesn't solve). MEASURED-ONLY doesn't fight CPU: accepts TPM never enforces, uses it only to raise cost of lying consistently to all quorum members.

## HARDWARE FINDINGS (x86-only, web)
- Quote/sign latency ~100s of ms, single-digit ops/s, never hot-path: TPM-Fail (USENIX Sec'20) ~200ms per TPM signature, 20ms initial poll doubling; Chrome fleet ECDSA P-256 p50 200ms, p95 600ms (~5 to 1.7 sig/s); Stian Kristoffersen 2024 dTPMs/fTPM single-digit sigs/s best-case; TCG imposes no minimum performance; monotonic counters only required 1x/5s (cTPM NSDI'14); NV flash-backed, slow, wear-limited.
- PCR bank mechanics extend-only, volatile, bank-fragile: PCR[N] = HASH(PCR[N] || ExtendArg) (Microsoft/Infineon docs); min 24 PCRs/bank; common dTPM SHA-1 + SHA-256 banks; volatile (reset on reboot); TPM2_Quote signs hash of selected PCRs + nonce + clock, NOT values themselves — verifier must separately fetch unsigned event log + PCR values and replay (log lives in host RAM); Seal bound to (bank, indices, values) — switching bank bricks keys even on identical config; systemd/GRUB/shim extend different PCRs (0–10 firmware, 8 cmdline, 9 files, 11–15 kernel/userspace).
- Measured-boot chain realities: SRTM (each component measures next); CRTM MUST be immutable per TCG spec — in practice rooted in mutable SPI flash. MITRE "BIOS Chronomancy": 51-byte tick patch to CRTM replays known-good hash, PCR0 stays good while BIOS owned; "Flea" persists across updates; many OEM SRTMs measured only last byte of BIOS. LPC-bus attacks: short pins / force TPM reset without CPU reset, replay recorded good-boot extends (Dartmouth; Kursawe; TCG Bus Protection Guidance 2023). DRTM/TXT bypass: Wojtczuk+Rutkowska (SMM unmeasured → infect SMM → bypass SINIT ACM measurement, forge dynamic PCRs 17–19); Han USENIX Sec'18 survey (SMM vulns → remote firmware rewrite invisible to SRTM).
- SMM/ME/microcode unmeasurable from inside: SMM more privileged than hypervisor; SMRAM dump/insert changes no PCR if done at runtime post-measurement (SmmPack 2024: runtime SMM exploit leaves PCRs frozen good + SPI-flash write + VBS bypass); ME separate core, no PCR coverage; microcode updates measured only as "invoked," not resulting behavior.

## THINK-2 (after findings)
Hardware confirms THINK-1 and kills PIN: PIN pins a slow, incomplete, replayable signal (200–600ms quote → cached PIN = "trust me, I was good 5 min ago"; SMM/tick attacker loves caches); PIN's seal looks like enforcement but isn't (unseal releases secret to RAM owned by CPU/SMM/ME; one good boot → permanent compromise if attacker persists in SMM); bank/log fragility makes PIN brittle operationally (BIOS update, bank switch, GRUB double-measure → mass lockout → operators widen allowlists/lengthen expiry → theater). MEASURED-ONLY survives: never asks TPM what it can't do; TPM is timestamped nonced evidence (Quote + eventlog) fed to outward quorum checking behavior (peer timing, cross-attestation, binary transparency, anomaly); one liar can't convince quorum; SMM blind spot must fool ALL diverse channels simultaneously. Don't fight CPU: let TPM talk, never let it decide.

## REASONS
Blind spots structural not bugs (SMM/ME/microcode/runtime-DMA leave PCRs good — PIN = guaranteed false negatives). Latency physics (quotes ms-scale, NV slower — only background evidence + cached quorum verdict, never synchronous PIN gate). Revocation/supply-chain (firmware CVE, OEM lie = outward distribution/quorum problem; PIN localizes a global problem and fails open at scale).

## PROVING EXPERIMENT (2 boxes + 1 verifier, 1 day)
A=clean, B=SMM/tick-simulated (patch UEFI variable or tick-replay hardcoding good PCR0 extend; or DXE SMM module keeping PCR log identical + runtime backdoor). Both request capability under (a) TPM-PIN policy (Quote verifies + PCRs allowlisted, 5-min expiry) and (b) MEASURED-ONLY quorum (verifier + peer cross-check nonce freshness + eventlog replay + timing/behavior check). PASS: PIN grants B (blind-spot + replay acceptance + expiry abuse); quorum denies B (nonce/log mismatch or peer divergence) while granting A with < quote-latency impact on hot path (quotes off-path). Measure quote p50/p95 to prove hot-path PIN infeasible.

## WHAT WOULD CHANGE MY MIND
Immutable externally-verified CRTM covering SMM/ME/microcode (DRTM measuring SMI handler + ME version + microcode rev into resettable-only dynamic PCRs) PLUS sub-ms bus-protected quotes with hardware freshness (no LPC/SPI replay, mandatory parametric encryption) PLUS fast revocation distribution. If all three ship in commodity x86, PIN with short expiry becomes defensible as local fast-path with quorum backstop. None exist today.
