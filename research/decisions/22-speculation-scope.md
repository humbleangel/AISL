# Decision brief 22/28 (cross-cutting) — speculation default scope

RECOMMENDATION: INVITATION-WINDOWS. Closed by default; explicit bounded unfenced regions with tripwire + PMU crosscheck. Default at every trust crossing (syscall, VMexit, IRQ, compartment call): LFENCE + BHB-clear (BHI_DIS_S/IBHF or SW loop) + VERW/L1D_FLUSH where MDS/L1TF applies + IBPB/RSB-stuff per policy. Compiler default = harden (SLH + retpoline + SSBD-aware), not bare. Unfenced window allowed only if: (a) declared in source with bounds (PC range, max instr/cycles, no secret loads, no indirects/rets inside or retpolined), (b) entered/exited through fence + BHB-clear, (c) runtime tripwire counts MACHINE_CLEARS + BR_MISP_RETIRED inside; over-threshold → trap/close + log. SECRET typing retained as optimization inside windows (shrink what must be fenced), never as the boundary.

## THINK-1 (from metal)
CPU does not have one "speculation" — it has 5+ predictors + buffers leaking independently: (1) cond-branch (v1) — LFENCE can stop; (2) indirect BTB/BHB (v2/BHI) — LFENCE at victim gadget does NOT fix poisoned predictor, need isolation/flush; (3) RSB (ret) — need stuffing, not LFENCE; (4) store-bypass / memory disambiguation (v4) — need SSBD or store-load LFENCE; (5) fill/store buffers, L1 (MDS/L1TF) — LFENCE IRRELEVANT, need buffer overwrite + flush (secret need not even be in victim's architectural path). So any scope saying "one mechanism everywhere" is wrong on metal. FENCE-everywhere invites LFENCE cargo-cult (and MFENCE ≠ speculation barrier). SECRET-only fails because MDS/BHI leak without secret-dependent branch in victim code, and implicit flows + store gadgets (v1.1/v1.2) escape taint. Closed-by-default with typed domain crossings is the only shape matching silicon: default deny speculation across trust boundaries, explicit bounded allow-regions inside.

## HARDWARE FINDINGS (x86-only, web)
- LFENCE stops v1, not v2/v4/MDS: Intel SA-00088 ("LFENCE... no later instruction will execute, even speculatively" for Bounds Check Bypass; use judiciously, overapplication kills perf).
- LFENCE-as-retpoline deprecated: Linux spectre_v2=retpoline,lfence now warns "not recommended... data leaks possible", weaker esp. SMT even non-SMT (kernel spectre docs; torvalds eafd987d).
- v2 needs eIBRS+retpoline/IBPB/STIBP/RSB-stuff, and eIBRS insufficient: BHB itself not isolated between modes; kernel disables retpoline only when eIBRS present; STIBP implied by eIBRS on Intel, explicit elsewhere (kernel spectre docs).
- BHI/Native-BHI breaks eIBRS: BHB-poisoning steers indirects despite eIBRS (>95% mispredict); fix = BHI_DIS_S + IBHF or SW BHB-clearing loop at syscall/VMexit + disable unpriv eBPF + SMEP; Native-BHI CVE-2024-2201 needs no eBPF (Intel BHI docs; Barberis USENIX'22; vusec/bhi-spectre-bhb; Phoronix).
- v4 needs SSBD, LFENCE only point-fix: LFENCE between specific store→load works; global fix is SSBD via IA32_SPEC_CTRL + microcode, default opt-in via prctl/seccomp not global for perf (Intel SSB docs).
- MDS/L1TF need VERW/L1D_FLUSH, not fences: VERW m16 with MD_CLEAR overwrites MDS buffers; L1D_FLUSH covers L1TF+MDS on affected parts; SMT-off required for full guest-to-guest (Intel MDS docs; kernel mds docs).
- PMU tripwire-grade only: BR_MISP_RETIRED.*, BR_MISP_EXEC.ALL_BRANCHES, MACHINE_CLEARS.{COUNT,MEMORY_ORDERING,SMC}, INT_MISC.CLEARS_COUNT exist (perfmon-events Skylake) but sampling, noisy, skid-prone, gameable; 6346 hidden events detect Spectre in lab (arxiv:2304.12072) ≠ boundary; PMU itself leaks (40 events exfiltrate DIV/MOV operands incl. SGX, arxiv:2502.10722 PMU-Data).
- SLH incomplete, retpoline still required: LLVM x86-slh (-lfence, -post-load, -ip via SP high bits) hardens loads not control flow; indirect/ret edges "best mitigated with retpoline" (llvm SpeculativeLoadHardening docs); USLH: no existing SLH stops all v1 variable-time arithmetic channel (Zhang USENIX'23).
- 2024–25 churn: Indirector (2024) old v2 guidance holds; Branch Privilege Injection (2025, INTEL-SA-01247): eIBRS race needs new microcode (Intel advisories).

## THINK-2 (after findings)
Findings confirm THINK-1 and kill two options: FENCE-BY-DEFAULT-EVERYWHERE fails closed in theory, open in practice (developers sprinkle LFENCE, miss BHB/RSB/MDS, tank perf, then remove fences to ship; Linux itself does case-by-case barrier_nospec() + pointer sanitization with listed gaps). SECRET-TYPING-ONLY fails sound (BHI/MDS leak secrets with no secret-typed branch in victim; SLH misses timing channels; type system can't see BHB state). PMU confirms tripwire role (anomaly crosscheck: MACHINE_CLEARS burst + BR_MISP burst around window; useless as enforcement — no trap-on-speculation, attacker-pollutable). Survivor: default-closed domains with hardware-appropriate close (LFENCE for v1 + BHB-clear/IBHF + IBPB/STIBP/eIBRS management + VERW/L1D_FLUSH at privilege cross + SSBD policy) + bounded declared measured open windows.

## REASONS
Only scope covering all 5 leak classes without pretending LFENCE fixes predictors/buffers; makes perf cost opt-in and auditable; matches Linux/Intel direction (selective LFENCE + HW predictor/buffer controls + BHB-clear), extended to language-enforced default.

## PROVING EXPERIMENT
Build 3 gadgets on eIBRS + SSBD-capable x86-64: (a) v1 bounds-bypass, (b) BHI cross-privilege indirect, (c) MDS VERW-omitted buffer sample. Show: (i) window-closed build blocks all 3 with PMU counters flat; (ii) one declared window over hot loop recovers >80% of fence-everywhere loss while counters stay flat and tripwire fires on injected poison; (iii) secret-typing-only build blocks (a) but leaks (b)/(c).

## WHAT WOULD CHANGE MY MIND
Toward FENCE-EVERYWHERE: workload proof that blanket-LFENCE + always-BHI_DIS_S + always-SSBD + always-VERW costs <5% on real AISL mix AND covers BHI/MDS without SMT-off (not true today). Toward SECRET-ONLY: formal + silicon proof that USLH + secret types close BHB/RSB/buffer channels with no domain flushes (contradicted by BHI + PMU-Data + MDS). Toward dropping PMU tripwire: evidence PMU noise causes >1% false-trap in production, or attacker reliably blinds MACHINE_CLEARS from guest (then keep bounded windows, drop crosscheck to debug-only).
